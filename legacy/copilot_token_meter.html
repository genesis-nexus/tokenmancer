01

The turn

One request = your prompt + everything in the window, in; the model's reply, out. Output tokens cost 4–10× more, so output discipline is the highest-ROI lever.

Type freely — input tokens update live.
DO add output rules: “Code only”, “Don’t restate”, “Changed code only” — up to 70% off. DON’T let it explain and restate your question at 4–10× output pricing.
DO default to Auto — routes simple tasks cheaply and applies a 10% structural discount.
DO keep system prompt + instructions identical across turns so they’re billed at the ~10× cheaper cached rate.
DON’T use Agent Mode for simple help — it re-sends the whole window across its reasoning loop. The single biggest credit drain.

02

What you loaded into the window

Your question is usually a tiny slice of the input. The rest is overhead you configured — open tabs, tool schemas, instruction bloat, and resent history — and you pay for all of it on every turn above.

DO keep 3–5 tabs — all tab contents are injected into every request. DON’T leave 20+ open.
DO scope toolsets (toolsets:[issues]). DON’T run the default 22-tool set or 15+ global servers.
DO treat copilot-instructions.md as a bug tracker. DON’T pack it with wiki content.
DON’T prompt piecemeal — each follow-up re-sends the full thread as input. DO use /new to reset.

04

Same work, every model

Identical window and output, priced across all tiers. Frontier can cost an order of magnitude more than Lightweight for an identical task — gate it to senior, multi-file work.

05

Retrieval & compression

Two levers that don't appear in the DOs/DONTs but dominate agent cost: how the agent finds code, and whether anything strips the noise. A code graph returns relationships, not file bodies; compression layers cut the input, output, and carried context.

DON’T let agents grep and read whole files each prompt. DO query a code graph — symbols + edges, ~50× less context.
In grep mode each file is read in full; in graph mode the query result barely moves regardless of how many files the answer spans.
Removes preamble/restatement from responses while keeping the reasoning. Doc cites up to 75% output reduction. (Bites only when output is verbose.)
Strips npm/cargo/test progress bars and logs before they hit context. Doc cites 80–90% off tool output. (Applies in grep mode, where the agent runs builds/tests.)
Sandboxes tool outputs so resent history shrinks. Doc cites up to 98% compression, extending long sessions.

Retrieval is the swing factor

06

Verify against real Copilot

The model predicts; this proves. VS Code logs the true token counts and AI Credit cost of every call. Read them and reconcile against the math here — per iteration, then per session.

1. In VS Code, open Copilot Chat → ⋯ → Show Chat Debug View (or Developer: Show Chat Debug View).
2. Each model call shows a usage block and a copilotUsage line in AI Credits.
3. Paste the usage JSON here — it computes the four-rate breakdown and total AIC, server rates used when present.
4. Run the same prompt verbose vs terse and diff the two copilotUsage lines: that's your saving, measured on real billing.
Used only if the pasted block has no token_details. The doc's table matches Sonnet / GPT-4.1 / mini; read the VS Code model hover for others.
